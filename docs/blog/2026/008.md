## 服务端：一条龙喵

`tcp_server.c` 把服务端的「五步走」写得明明白白：**socket → bind → listen → accept → 收发**喵：

```c
int fd = socket(AF_INET,SOCK_STREAM,0);          // 1. 创建套接字
if(fd == -1){
    perror("socket");
    exit(1);
}
struct sockaddr_in server_addr;
server_addr.sin_family = AF_INET;
server_addr.sin_port = htons(9191);              // 端口：注意字节序！
server_addr.sin_addr.s_addr = htonl(INADDR_ANY); // 监听所有网卡

if(bind(fd,(struct sockaddr*)&server_addr,sizeof(server_addr)) == -1){ // 2. 绑定
    perror("bind");
    close(fd);
    exit(1);
}

if(listen(fd,10) == -1){                         // 3. 监听
    perror("listen");
    close(fd);
    exit(1);
}
printf("Waiting for connect...\n");

int client_fd = accept(fd,NULL,NULL);            // 4. 接入客户端
if(client_fd == -1){
    perror("accept");
    close(fd);
    exit(1);
}
printf("Client connected!\n");

char buf[1024];
ssize_t n = recv(client_fd,buf,sizeof(buf)-1,0); // 5. 收数据
if(n > 0){
    buf[n] = '\0';
    printf("Received:: %s\n",buf);
    char *response = "Hello from server";
    send(client_fd,response,strlen(response),0); //    再发回去
}
```

整个流程一气呵成喵！主人还把每个函数失败时的 `perror` + 清理都写上了——`close(fd)` 绝不漏，这份「每个失败路径都要干净退出」的肌肉记忆，秋秋在 IPC 那篇就夸过，现在还在，太好了喵！

## 客户端：主动出击喵

`tcp_client.c` 是另一条主线：**socket → connect → 收发**喵：

```c
int client_fd = socket(AF_INET,SOCK_STREAM,0);
if(client_fd == -1){
    perror("socket");
    exit(1);
}
struct sockaddr_in target_addr;
target_addr.sin_family = AF_INET;
target_addr.sin_port = htons(9191);

if (inet_pton(AF_INET, "127.0.0.1", &target_addr.sin_addr) != 1) {
    perror("inet_pton");
    close(client_fd);
    return 1;
}
if(connect(client_fd,(struct sockaddr*)&target_addr,sizeof(target_addr)) == -1){
    perror("connect");
    close(client_fd);
    exit(1);
}
printf("Server connected!\n");
char *message = "Hello from client";
send(client_fd,message,strlen(message),0);   // 发

char buf[1024];
ssize_t n = recv(client_fd,buf,sizeof(buf)-1,0); // 收
if(n > 0){
    buf[n] = '\0';
    printf("Received:: %s\n",buf);
}
sleep(3);
close(client_fd);
```

`inet_pton` 把 `"127.0.0.1"` 点分十进制字符串转成二进制地址，转失败返回 0（主人检查的是 `!= 1`，很严谨喵）。

## 秋秋要敲黑板的三个细节喵

**1. 网络字节序喵！** 主人的代码里 `htons(9191)`、`htonl(INADDR_ANY)` 一个都没少喵。端口号和 IP 都是**多字节整数**，网络传输统一用大端（网络字节序），所以主机字节序要转过去。忘了 `htons` 的话，端口 9191 会变成另一个莫名其妙的数，连都连不上喵——这是每个 socket 新手第一个坑，主人直接绕过去了喵！

**2. `accept` 才建立真正的连接喵。** `listen` 只是让内核监听，`accept` 才是从等待队列里取一个客户端、返回一个**专门通信的套接字**喵。主人代码里 `accept` 之后用的是 `client_fd` 收发，原来的 `fd` 还能继续 `accept` 下一个连接——这个「监听套接字 / 通信套接字」分离的概念，主人理解得很对喵！

**3. `SO_REUSEADDR` 喵。** 在 `tcp_mini_server_test.c` 里主人还用了 `setsockopt(SO_REUSEADDR)`——避免服务器刚关掉，端口还处于 TIME_WAIT 状态导致重启 bind 失败的经典问题喵：

```c
int opt = 1;
setsockopt(server_fd,SOL_SOCKET,SO_REUSEADDR,&opt,sizeof(opt));
```

这个小细节是踩过坑才知道的，主人已经会了喵！
