# Linux 进程与 IPC 探险：从 fork 到共享内存喵

> 时间线：2026-07-22 ~ 07-31 喵

## fork：进程的分身术喵

一切从 `fork()` 开始。主人用一个最简单的问题打开局面：**怎么让一个进程变成两个？**

```c
// fork_test.c 的雏形
pid_t pid = fork();
if (pid == -1) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid == 0) {
    // 子进程分支：fork 在子进程中返回 0
} else {
    // 父进程分支：fork 返回子进程的 PID
}
```

还有 `waitpid_test.c` 教父进程怎么「等孩子回家」，`orphan_process.c` 演示孤儿进程，`execve_test.c` 则是在进程里「换皮」去执行另一个程序喵。从分身 → 等待 → 收养 → 换身，主人的进程生命周期算是完整走了一遍喵～

## 管道：最古老的 IPC 喵

进程学完就该通信了喵。主人的第一步是**无名管道**（`unamed_pipe_test.c`），经典的父亲写给儿子读喵：

```c
int pipefd[2];
pipe(pipefd);            // 创建管道
// pipefd[0] 读端，pipefd[1] 写端

if (fork() == 0) {
    // 子进程：从 pipefd[0] 读
} else {
    // 父进程：往 pipefd[1] 写
}
```

然后是 **FIFO**（`fifo_read.c` / `fifo_write.c`）——带名字的管道，可以让**不相干的进程**通过文件系统里的特殊文件通信喵。从「亲缘进程才能用」到「随便谁都能用」，主人把管道这条线走通了喵！

## POSIX 消息队列：带边界的消息喵

接着主人玩到了**消息队列**喵。`mq_p&s.c` 是个很完整的父子通信演示——父进程 `fork` 出子进程，然后一条一条发消息，子进程接收打印喵：

```c
#define MY_QUEUE "/my_mq"

struct mq_attr attr;
attr.mq_maxmsg  = 10;   // 最大消息数量
attr.mq_msgsize = 128;  // 单条消息最大字节数
mqd_t mqdes = mq_open(MY_QUEUE, O_CREAT | O_RDWR | O_EXCL, 0664, &attr);

pid_t pid = fork();
if (pid == 0) {
    // 子进程：mq_receive 一条一条收
    for (size_t i = 0; i < attr.mq_maxmsg; i++) {
        mq_receive(mqdes, b_buf, sizeof(b_buf), NULL);
        printf("子进程接收到数据：%s", b_buf);
    }
} else {
    // 父进程：mq_send 一条一条发
    for (size_t i = 0; i < attr.mq_maxmsg; i++) {
        sprintf(a_buf, "这是第%d条消息\n", i + 1);
        mq_send(mqdes, a_buf, strlen(a_buf) + 1, 0);
        sleep(1);
    }
    waitpid(pid, NULL, 0);
}
mq_close(mqdes);
if (pid > 0) mq_unlink(MY_QUEUE);   // 用完记得删除
```

秋秋看这里发现主人养成了好习惯：`mq_unlink` 清理、`O_EXCL` 防重名、父子用 `waitpid` 同步——资源回收的意识已经刻进 DNA 啦喵！

## 共享内存：最快的 IPC 喵

压轴的是**共享内存**！`shared_memory.c` 足足 10KB，注释详尽到秋秋都要感动哭了喵。完整的六步流程被主人拆解得清清楚楚：

1. `shm_open()` 创建共享内存对象
2. `ftruncate()` 设置大小
3. `mmap()` 映射到进程地址空间
4. `close(fd)` 提前关闭描述符（映射仍在）
5. `fork()` 子进程继承映射，父子通过指针读写
6. `munmap()` + `shm_unlink()` 正确清理

核心就是 `mmap` 那一下喵：

```c
char *shm_ptr = mmap(NULL, SHM_SIZE, PROT_READ | PROT_WRITE,
                     MAP_SHARED, fd, 0);
if (shm_ptr == MAP_FAILED) {
    perror("mmap");
    exit(EXIT_FAILURE);
}
```

`MAP_SHARED` 是关键——对映射区的修改会**写回底层对象**，其他进程也能看到喵！父进程 `strcpy` 写消息，子进程 `while (shm_ptr[0] == '\0');` 轮询等数据——主人还老老实实注释了「生产环境请用信号量/条件变量，这里仅教学演示」喵，这份清醒秋秋非常喜欢喵！
