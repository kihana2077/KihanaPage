# Linux 进程与 IPC:从 fork 到共享内存

接上一篇,这一篇进入 Linux 并发里更核心的一块——进程与进程间通信(IPC)。`process_test/` 下的代码从 7 月下旬开始铺开。

## fork:怎么让一个进程变成两个

一切的起点是 `fork()`,用最简单的问题打开局面:

```c
// fork_test.c 的雏形
pid_t pid = fork();
if (pid == -1) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid == 0) {
    // 子进程分支：fork 在子进程中返回 0
} else {
    // 父进程分支：fork 返回子进程的 PID
}
```

配套练习:`waitpid_test.c`(父进程等子进程结束)、`orphan_process.c`(孤儿进程)、`execve_test.c`(在进程里执行另一个程序)。从分身 → 等待 → 收养 → 换身,进程生命周期基本走了一遍。

## 管道与 FIFO

无名管道(`unamed_pipe_test.c`)适合父子进程:

```c
int pipefd[2];
pipe(pipefd);            // 创建管道
// pipefd[0] 读端，pipefd[1] 写端

if (fork() == 0) {
    // 子进程：从 pipefd[0] 读
} else {
    // 父进程：往 pipefd[1] 写
}
```

FIFO(`fifo_read.c` / `fifo_write.c`)是有名字的管道,不相关的进程也能通过文件系统里的特殊文件互通。从「亲缘进程才能用」到「随便谁都能用」,管道这条线算是走通了。

## POSIX 消息队列

`mq_p&s.c` 是完整的父子通信演示:父进程 fork 出子进程,`mq_send` 一条条发,子进程 `mq_receive` 接收打印。

```c
#define MY_QUEUE "/my_mq"

struct mq_attr attr;
attr.mq_maxmsg  = 10;   // 最大消息数量
attr.mq_msgsize = 128;  // 单条消息最大字节数
mqd_t mqdes = mq_open(MY_QUEUE, O_CREAT | O_RDWR | O_EXCL, 0664, &attr);

pid_t pid = fork();
if (pid == 0) {
    // 子进程：mq_receive 一条一条收
    for (size_t i = 0; i < attr.mq_maxmsg; i++) {
        mq_receive(mqdes, b_buf, sizeof(b_buf), NULL);
        printf("子进程接收到数据：%s", b_buf);
    }
} else {
    // 父进程：mq_send 一条一条发
    for (size_t i = 0; i < attr.mq_maxmsg; i++) {
        sprintf(a_buf, "这是第%d条消息\n", i + 1);
        mq_send(mqdes, a_buf, strlen(a_buf) + 1, 0);
        sleep(1);
    }
    waitpid(pid, NULL, 0);
}
mq_close(mqdes);
if (pid > 0) mq_unlink(MY_QUEUE);   // 用完记得删除
```

这里的收尾做得比较规范:`mq_unlink` 清理、`O_EXCL` 防重名、父子用 `waitpid` 同步。

## 共享内存

压轴是共享内存。`shared_memory.c` 把流程拆成六步:`shm_open()` 创建 → `ftruncate()` 设大小 → `mmap()` 映射 → `close(fd)` 提前关描述符(映射仍在)→ `fork()` 子进程继承映射 → `munmap()` + `shm_unlink()` 清理。

核心是 `mmap`:

```c
char *shm_ptr = mmap(NULL, SHM_SIZE, PROT_READ | PROT_WRITE,
                     MAP_SHARED, fd, 0);
if (shm_ptr == MAP_FAILED) {
    perror("mmap");
    exit(EXIT_FAILURE);
}
```

`MAP_SHARED` 让对映射区的修改写回底层对象,其他进程也能看到。父进程 `strcpy` 写消息,子进程 `while (shm_ptr[0] == '\0');` 轮询等数据——代码里也老老实实注释了「生产环境请用信号量/条件变量,这里仅教学演示」。

## 小结

| 机制 | 适合场景 |
|------|---------|
| 无名管道 | 父子进程 |
| FIFO | 无亲缘进程 |
| 消息队列 | 带边界、结构化消息 |
| 共享内存 | 最快、数据量大 |

这一阶段相比初学时期开始注意防御性检查和资源释放,算是在从「能跑」往「写干净」靠拢。
