# 给大模型套上缰绳:手写 bounded-shell-mcp

`bounded-shell-mcp` 是一个受控的命令执行 MCP server。出发点很直接:如果让大模型直接在终端执行命令,安全性很难保证,所以给它套上几层边界:

- 命令直接用 `argv` 执行,**不经过 shell**(减少注入面)
- 可执行文件必须出现在配置的 allowlist 里
- 默认**禁止网络**,沙箱模式需要 Docker/Podman
- `sudo`/`su`/`doas` 只能**审批后执行**
- 审计只保留**元数据 + 输出哈希**,不存输出原文

整体流程是「先预检、再执行、高风险要审批」,想避免大模型「猜命令 — 失败 — 再猜」的循环。

## 一次性审批令牌

高风险命令的处理没有用简单的布尔字段(容易被绕过),而是用一次性、短期、绑定请求指纹的审批令牌:

```python
class ApprovalStore:
    def create(self, fingerprint: str) -> str:
        self._purge_expired()
        token = secrets.token_urlsafe(32)   # 32字节随机令牌
        self._approvals[token] = Approval(
            fingerprint=fingerprint,
            expires_at=time.monotonic() + self._ttl_seconds,
        )
        return token

    def consume(self, token: str, fingerprint: str) -> tuple[bool, str]:
        ...
        if not secrets.compare_digest(approval.fingerprint, fingerprint):
            return False, "approval_command_mismatch"
        approval.used = True
        return True, "approved"
```

几个细节:

- `secrets.token_urlsafe(32)` — 密码学安全随机源,不是 `random` 那种伪随机
- `compare_digest()` — 恒定时间比较,防时序攻击
- `used = True` — 令牌用完即作废
- 校验绑定 `fingerprint` — 审批的是「这一条具体的命令」,改一个参数令牌就失效

## 策略引擎

`PolicyEngine.preflight()` 是整套策略的核心,把一条命令的风险汇总成一个决策:

```python
# 命令在 allowlist 里吗？
allowlisted_subcommands = self.settings.allowlist.get(name)
if allowlisted_subcommands is None:
    decision = Decision.DENY

# 网络命令 + 配置允许？
if normalized.network == "enabled":
    risks.append("network")

# 需要 PTY 的交互程序（vim/top/ssh -t）？
if name in PTY_COMMANDS:
    decision = Decision.DENY

# setuid 可执行文件 —— 永远拒绝
if executable_path.stat().st_mode & stat.S_ISUID:
    decision = Decision.DENY

# sudo/su/doas —— 需要审批
if name in PRIVILEGE_COMMANDS:
    decision = Decision.APPROVAL_REQUIRED

# 有风险标记但还没被拒 → 升级为审批
if decision is Decision.ALLOW and risks:
    decision = Decision.APPROVAL_REQUIRED
```

决策只有四档:`ALLOW` / `APPROVAL_REQUIRED` / `DENY` / `BACKEND_UNAVAILABLE`,加上带 `remediation`(修复建议)的 `Diagnostic`。对 `ssh` 这类交互程序还写了非交互替代建议:

```python
@staticmethod
def _noninteractive_alternative(name: str) -> str | None:
    return {
        "top": "Use top -b -n 1 instead.",
        "vim": "Use a file editing tool instead.",
        ...
    }.get(name)
```

「拒绝,但告诉你还可以怎么干」——建设性拒绝比冷冰冰的 deny 体验好。

还有个有意思的分类:`_classify()` 把 `python`/`python3`/`pytest` 都归为 `arbitrary_code_execution`——让大模型执行 Python 基本等于让它跑任意代码,这么归类是合理的。
